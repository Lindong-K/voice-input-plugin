# 语音输入插件 · 创造模式提示词

> 用途：把以下内容整体复制，粘贴到「创造模式」，即可生成「语音输入转文字」插件。
> 需求来源：当有大量内容要告诉 AI 时，不再只能打字，可以口述。

---

```text
# 角色
你是资深的前端 Web 与浏览器端插件工程师。请开发一个「语音输入插件」：为聊天界面增加"点击说话 → 自动转文字"的能力——当用户有大量内容要告诉你时，可以直接口述，不再只能打字。

# 平台约束（必须先认清，写进你的方案）
语音采集与识别必须发生在**浏览器端**：麦克风权限、录音、转写、写入输入框，全部在用户的浏览器内完成。
- 若当前运行环境（例如模型侧动态插件机制）只能给模型加工具、无法向浏览器界面注入 UI，你必须**首先明确报告这个阻塞点**，并给出可行的替代宿主（浏览器扩展 / 油猴脚本 / 独立本地页面 / 客户端插件），再动手实现。
- 严禁退化成"模型侧工具"假装实现——模型听不到麦克风，那不是语音输入。
- 首选宿主是聊天 Web 界面本身（运行于 http://127.0.0.1:3080 之类的 localhost 安全上下文）。

# 硬性设计原则（必须遵守）
1. 不依赖任何服务端中转：默认方案完全用浏览器内置语音识别（Web Speech API），无需 API Key、无需上传音频。
2. 识别结果默认只**填入消息输入框（可编辑）**，绝不自动发送——用户先核对、修改，再手动发送；除非用户显式开启"说完即发"开关。
3. 无感不打断：识别过程中用户仍可打字、编辑输入框；插件不得清空或覆盖已有输入，识别文字应**追加到光标处/末尾**。
4. 隐私最小化：不录制保存音频、不私自上传；若因浏览器不支持需要降级方案，必须先向用户明示，不得静默换用第三方录音上传。
5. 插件必须能随界面重渲染自动恢复（聊天 UI 是动态渲染的），卸载/禁用时完全清理（移除按钮、停止识别、释放麦克风、移除样式与事件监听）。

# 技术实现要求（每条都是踩坑换来的，务必遵循）
1. 首选 Web Speech API：`SpeechRecognition`（Chrome/Edge 为 `window.webkitSpeechRecognition`），localhost/HTTPS 安全上下文下可直接使用，免 Key 免服务器。
2. 识别参数：`lang: 'zh-CN'`（默认中文普通话，做成可配置）；`continuous: true`（连续听写，支持长段口述）；`interimResults: true`（实时显示中间结果，避免"说完才出字"）。
3. 结果处理：`onresult` 中把 `event.results` 的**最终结果(final)**追加进输入框（保留已有内容，追加到末尾或光标位置）；**中间结果(interim)**显示在输入框旁的浮动预览条上；最终落定后清空预览条。
4. 状态机与 UI：按钮至少三态——空闲(灰) / 监听中(红点+脉冲动画+显示"正在聆听…"与已识别字数) / 错误(黄)；点击切换开始/停止；停止后输入框自动聚焦。
5. 错误处理必须全覆盖：
   - `not-allowed`：用户拒绝麦克风权限 → 明确提示如何开启（含地址栏权限按钮指引）；
   - `no-speech`：没听到声音 → 自动重试一次并提示"请说话"；
   - `network` / `service-not-allowed`：识别服务不可用 → 明确报错，不静默无限重试；
   - `audio-capture`：无麦克风设备 → 明确提示。
   - 识别器意外结束（`onend` 且非用户主动停止）时自动重启一次，避免"说到一半断了"。
6. DOM 注入与恢复：用 MutationObserver 监听输入区，按钮被重渲染移除后自动重新挂载；DOM 锚点用稳定的选择器（placeholder / aria 属性），不依赖易变的 class 名。
7. 兼容降级：检测 `window.SpeechRecognition || window.webkitSpeechRecognition`；不支持时按钮置灰并提示"当前浏览器不支持语音输入，请使用 Chrome/Edge"，同时展示【增强档】说明，但默认不启用。
8. 自动标点：识别文本按句补全中文标点（，。？！），按语义断句，不在词中间生硬断开。

# 功能需求
1. 在聊天输入框右侧（紧邻发送按钮）注入一个麦克风图标按钮：圆角、无边框、浅色底，悬停提示"语音输入"，尺寸 ≤ 32px，不遮挡输入文字。
2. 点击开始监听：按钮变红 + "聆听中"脉冲动画；说话内容实时以中间结果显示在输入框下方的浮动预览条（浅色半透明底）。
3. 再次点击（或说完停顿）停止：最终文字**追加**到输入框末尾（保留原内容），预览条消失，输入框聚焦。
4. 连续多段口述：一次监听内说多句逐句落定；长段口述不受 60 秒限制（continuous 模式 + 静音超时自动分段）。
5. 配置项（默认值合理，放在插件配置区）：
   - `language`（默认 `zh-CN`）
   - `autoSend`（默认 `false`：识别完不自动发送）
   - `punctuation`（默认 `true`：自动补标点）
   - `autoRestart`（默认 `true`：意外中断自动重启一次）
   - 可选【增强档】`whisperEndpoint`（默认空）：填了才启用——用 MediaRecorder 录制 WebM 音频上传到该端点（本地 Whisper 服务）转写，作为 Web Speech API 质量不佳时的后备；为空则完全不涉及音频上传。
6. 键盘可达性（无障碍）：Tab 可聚焦按钮，Enter/Space 触发开始/停止。
7. 不干扰：识别中不劫持键盘焦点，用户仍可打字编辑。

# 验证要求（必须执行并输出结果）
1. 环境自检：启动时输出能力检测报告——浏览器是否支持 SpeechRecognition、页面是否安全上下文（https/localhost）、麦克风是否可用。
2. 手动测试清单（逐项给出结果，禁止跳过）：
   - 点击开始 → 出现监听状态与权限请求（首次）→ 说话 → 中间结果实时出现 → 停止 → 文字进入输入框且保留已有内容；
   - 输入框已有文字时再说一段 → 文字追加到末尾而非覆盖；
   - 拒绝麦克风权限 → 出现明确指引，不崩溃不静默；
   - 静默 10 秒无语音 → 自动停止并提示，不无限空转；
   - 连续口述 2 分钟以上 → 分段落定、无内容丢失；
   - 页面重渲染（发送消息/切换会话）→ 按钮自动恢复、识别状态不残留；
   - 插件卸载/禁用 → 按钮移除、麦克风释放、无残留监听器与定时器（DevTools 确认）。
3. 输出"验证报告"：每项给 通过/失败 + 实际表现说明；任何一项失败必须修复后重测。

# 美学要求
- 与聊天界面风格统一：按钮用主题强调色（建议 #0969DA 同系）浅色底、深色图标；聆听状态用红色脉冲圆点 + 轻微缩放动画。
- 预览条：圆角 8px、浅灰半透明底（rgba(0,0,0,0.05)）、次要文字色（#8B949E）、字号与输入框一致。
- 动画只做必要反馈（脉冲、淡入淡出），单次 < 300ms，不花哨、不遮挡输入内容。

# 交付物
1. 插件源码（含依赖清单、安装/注入方式；动态插件请给出注册命令与 pluginId）
2. 使用说明（README：功能、用法、配置项、浏览器兼容性、隐私说明）
3. 能力检测报告 + 手动测试验证报告（含上面清单每项结果）
4. 一次端到端演示记录：从"点击按钮 → 口述一段 30 字以上的话 → 文字进入输入框"的完整过程描述
```

## 使用说明

1. 复制上方代码块内的全部内容，粘贴到创造模式。
2. 可追加你的偏好，例如：默认识别语言（方言/中英混说）、按钮放左侧还是右侧、是否要"说完即发"开关、是否接本地 Whisper 服务地址。
3. 生成的插件应自带验证；跑完后会把"能力检测报告 + 手动测试清单结果"交给你——那就是它合格的证据。
4. 如果创造模式报告"无法向浏览器界面注入 UI"，说明宿主只支持模型侧工具，需要换浏览器扩展/油猴脚本宿主——这是提示词里写明的合理阻塞点，不是失败。
