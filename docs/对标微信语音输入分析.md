# 对标分析：微信语音转文字 vs 本项目语音输入插件（网页版视角）

> 目标：以微信「语音转文字」的成熟体验为基准，找出本项目的不足并改进。
> 注意：本项目是 **DeepSeek Harness 网页版**（桌面端，鼠标键盘为主），
> 对标时须把微信**移动端触屏交互**（按住说话、上滑取消）映射成**桌面端等价物**，
> 不能照搬触屏手势。
> 分析日期：2026-08-15

## 一、逐项对比

| 维度 | 微信（移动端为主） | 桌面端等价物 | 本项目（v4 / pkg-7） | 差距与结论 |
|---|---|---|---|---|
| 交互方式 | 按住说话 / 松开发送 | 点击开关（桌面端更自然） | 点击开关 ✅ | 无（保持桌面默认；按住说话降为可选） |
| 取消机制 | 上滑取消（触屏手势） | **监听中「✕ 取消」按钮 + Esc 键** | 无 ❌ | **大 → 已实现** |
| 取消后回滚 | 手势取消直接丢弃 | 取消应**撤回本次已追加的文字** | 无 ❌ | **大 → 已实现**（自动回滚会话起点） |
| 标点 | 智能断句：？/！/。 | 同左（平台无关） | 只补「。」 ❌ | **中 → 已实现**（疑问/感叹检测） |
| 实时反馈 | 顶部大字实时显示 | 输入框下方预览条 | 预览条 ✅ | 无 |
| 长段口述 | 连续流 / 分段 | 同左 | continuous 连续听写 ✅ | 无（本项更强） |
| 说完即发 | 语音消息松开即发 | autoSend 选项 | 已有（默认关）✅ | 无 |
| 点词修正 | 点字换候选词 | 候选词接口依赖大 | 无 | 远期待办（依赖候选词源） |
| 隐私 | 音频上传微信服务器 | — | 浏览器内置识别，音频不出本机 | 本项目更优 |

## 二、结论：网页版值得改的 3 项

1. **监听中可取消**（桌面版"上滑取消"）：
   - 监听时预览条显示「✕ 取消」按钮；
   - **Esc 键**随时放弃本次识别。
2. **取消自动回滚**：取消时把本次会话追加进输入框的文字**撤回**到会话开始前的草稿
   （若用户在识别期间额外编辑过内容，则不覆盖、保留现状）。
3. **智能标点**：疑问句补「？」、感叹句补「！」、默认「。」。

> 按住说话（hold）保留为**可选配置**（触屏/触控板用户可用），默认仍是桌面端点击开关。

## 三、实现（v5 / pkg-8）

- `store.config.inputMode = 'toggle'（默认） | 'hold'`
- 取消：`cancelRecognition()` —— abort 识别器（不触发收尾回放）、清缓冲、
  校验草稿未被额外编辑后回滚到会话起点；预览条取消按钮 + Esc 均走此函数
- 智能标点：`addPunctuation` 疑问/感叹词检测
- 按住模式（可选）：pointer 捕获 + 上滑 50px 触发「松开取消」
